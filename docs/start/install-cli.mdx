Oxygen is delivered as a hosted product at
**[app.oxygen-hq.com](https://app.oxygen-hq.com)** — sign up, connect your
data, and start asking questions. There is nothing to install to use the
product.

The **`oxyc` CLI** is an optional companion that works with your Oxygen
deployment from a terminal, a CI job or an AI coding agent: check your project's
files before you push them, run automations and SQL on your deployment, gate
pull requests on a clean compile, and connect your editor over MCP. You do
**not** need it to use Oxygen.

<Note>
If you just want to ask questions of your data, use the web app — skip this
page.
</Note>

## Install

`oxyc` is published to npm as [`@oxy-hq/cli`](https://www.npmjs.com/package/@oxy-hq/cli).
It needs Node.js 20 or later:

```bash
npm install -g @oxy-hq/cli
```

Or run it without installing:

```bash
npx @oxy-hq/cli --help
```

### Verify

```bash
oxyc --version
```

### Update

```bash
npm install -g @oxy-hq/cli@latest
```

### Sign in

Commands that talk to your deployment need a login. `oxyc login` opens your
browser (or prints a URL and a code when there is no browser):

```bash
oxyc login
oxyc whoami
```

## Basic commands

The CLI is self-documenting — run `oxyc --help`, or `oxyc <command> --help` for
any subcommand. The commands you'll reach for most:

| Command | What it does |
| --- | --- |
| `oxyc validate` | Check your project's files, offline |
| `oxyc compile <branch>` | Compile a branch on your deployment, as a CI gate |
| `oxyc run <file>` | Run an automation or a `.sql` file on your deployment |
| `oxyc evals run` | Run agent tests (`.test.yml`) on your deployment |
| `oxyc mcp` | Expose Oxygen to your editor over MCP |

### Validate your project

`oxyc validate` checks your `config.yml`, automations, agents, views and topics.
It runs offline, needs no login, and exits `9` when it finds a problem:

```bash
oxyc validate
```

### Check a branch before it merges

`oxyc compile` compiles a branch on your deployment without serving it, so a
pull request can fail before a broken change reaches production:

```bash
oxyc compile my-branch --workspace <workspace-id> --wait
```

The Oxygen project template runs this in CI for you.

### Run an automation

`oxyc run` starts an automation or a SQL file on your deployment and prints the
result. It runs the automation your deployment has compiled, so push a change
first; a SQL file's text is sent and runs against the deployed database of that
name:

```bash
oxyc run my_report.automation.yml --workspace <workspace-id>
oxyc run queries/weekly.sql --database warehouse --workspace <workspace-id>
```

Agent tests run the same way, with
[`oxyc evals run`](/guide/build/test-evaluate/testing).

### Expose Oxygen to your editor over MCP

MCP-compatible tools such as Cursor, Claude Desktop and Claude Code reach Oxygen
through `oxyc mcp`:

```bash
claude mcp add oxyc -- npx -y @oxy-hq/cli mcp --login --env production
```

See [MCP →](/guide/build/embed-extend/mcp) for editor configuration.

<Note>
**Coming from `oxy`?** The commands customers ran from the old `oxy` binary
moved to `oxyc`: `oxy validate`, `oxy run`, `oxy agentic`, `oxy sync` and
`oxy looker test` are now `oxyc validate`, `oxyc run`, `oxyc agentic`,
`oxyc sync` and `oxyc looker test`. They run on your deployment rather than on
your machine, so they need only a login, not your warehouse or LLM credentials.
</Note>
